# Firestore Rules Analysis: Shared Sheep Contacts

Target: `projects/outreach-slot-availability/databases/(default)`, Standard edition, `asia-southeast1`.

## Collections and models in current rules/app

- `users/{uid}`: legacy profile; owner read, writes denied.
- `users_public/{uid}`: UID, display name, photo, role, academic details, membership approval fields.
- `users_private/{uid}`: UID, email, phone and private/profile details.
- `app_settings/main`: global `autoApproveMembers` boolean and `updatedAt` timestamp.
- `semesters/{semesterId}`: semester name, active flag, optional date fields.
- `availabilities/{availabilityId}`: owner UID, semester ID, list of slots.
- `events/{eventId}`: name, dates, creator identity and timestamps.
- `eventSignups/{signupId}`: user, event, date and slot.
- `eventPairings/{pairingId}`: event, slot, creator and groups.
- `contacts/{contactId}`: creator UID/name, contact name/phone/gender, progress/status lists and maps, remarks, created/updated timestamps, optional linked account and partner fields.

## Query and access patterns found

- Contacts queried by `createdById` and `createdAt DESC`, `linkedByUid` and `createdAt DESC`, or `linkedUserId`; entire contacts collection ordered by `createdAt DESC`; filtered public users by membership status. New shared-contact query: `outreachPartnerIds array-contains uid` (no compound index needed; sort merged results locally).
- Public user queries use membership status or role, sometimes `displayName` order and limits; user picker reads approved users and, in single-link mode, contacts to exclude already-linked accounts.
- Semester queries read all semesters or filter active semesters.
- Availability queries read by semester ID.
- Event queries order by creation time; signup queries filter by user ID or event ID + slot ID; pairings use deterministic document IDs.
- User profile, private profile, settings and specific contact documents are read by document path.

## Security decisions and adversarial checks

- Preserve `linkedUserId` as the single account represented by a sheep; collaborators are stored separately as `outreachPartnerIds` and display names.
- Only the contact creator/organizer can edit partner IDs/names. A partner update is limited to contact content and cannot modify creator, timestamps, linked-account fields, or the partner list.
- Partner IDs are capped at 10 and ID/name list lengths must match. The owner explicitly grants sharing by choosing approved CLC accounts in the UI.
- Unauthenticated and non-member reads remain denied by the existing `isMember()` contacts rule.
- Non-partner update attempt fails because their UID is absent from the resource partner list.
- Partner ownership/share-list escalation attempt fails because the partner update allowlist excludes creator, linked-account, and partner fields.
- Creator UID and creation timestamp modification remain denied by existing immutable-field checks.
- Schema pollution and malformed required contact data remain denied by `validContact` and its allowed-key list.
- Rule syntax will be checked by Firebase CLI deployment. No emulator rules test suite is configured in the repository.
